# H2 Evaluator #87 — independent no-key archive API feasibility audit
**Date:** 2026-11-13 (read-only research; no Tradebot/BRAIN changes, no blockchain transactions).

## Verdict: current source is NOT sufficient for the canonical intent

The [current #87 specification](https://github.com/telegraphprotocol/bounties/issues/87) defines deterministic `ONCHAIN_METRIC_VERIFY_GENERAL` as a historic native-balance **or** transaction-count request, with exact pinned block, on Ethereum, Polygon, or Arbitrum.

The prior YAML candidates [v1](../data/truth_source_eth_balance_v1.yaml) and [v3](../data/truth_source_eth_balance_v3.yaml) do **not** prove end-to-end correctness for all these inputs. The v1 signed evaluation row was stored at HTTP 200 but later marked **`rejected/source_unparseable`** (not eligible). V2 and V3 have not been uploaded. Locally passing unit tests **do not replace** the node's validation and curation verdict.

## Schema-validation blocker

The [official Anjoman guide](https://anjoman.ai/docs/scoring/contribute-evaluation-data) allows a `truth_source` row with YAML as a string **or** JSON document as an object. Therefore switching v1 from a YAML string to v2 JSON object is **not an evidenced fix**. Neither the documented `anjoman.ai/dashboard/validate` endpoint (HTTP 405) nor `integrate.telegraphprotocol.com/api/validate` (HTML 200, rather than JSON validation result) returned actionable miner-schema diagnostics on 2026-11-13.

The private node validator could not be independently run using the available public source. Consequently the previous `source_unparseable` root cause is **unresolved**. A new signed POST would be an unverified retry, not a validated correction.
